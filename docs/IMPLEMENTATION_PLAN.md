# 益屿平台 — 未完成功能实现计划

> 更新日期：2026-08-03 | 基于项目价值评估报告

---

## 一、功能优先级矩阵

|  | **高用户价值** | **低用户价值** |
|---|---|---|
| **低实现难度** | ⭐ **立即做** — 用户画像基础、活动搜索增强、文件上传、推荐系统MVP | 🔜 **排期做** — SOP模板库、活动复盘报告 |
| **高实现难度** | 🎯 **规划做** — AI文案生成、回忆相册、游戏化模块 | ⏳ **暂缓** — 沟通协作/工单系统 |

## 二、分阶段实现计划

### Phase 1：核心功能补全（1-2 周）

> 目标：让平台从"能跑"变成"能用"，补齐 MVP 缺失的基础体验

#### 1.1 用户画像基础
| 项 | 说明 |
|---|---|
| **数据模型** | User 表新增 `interests` (JSON)、`activity_history_score` (JSON)、`location_preference` (String) |
| **API** | `PUT /api/v1/users/me/interests` — 更新兴趣标签；`GET /api/v1/users/me/profile-completion` — 画像完整度 |
| **前端** | Profile 页增加兴趣标签选择器（多选 chip） |
| **工作量** | 2 人天 |

#### 1.2 基于标签的简单推荐
| 项 | 说明 |
|---|---|
| **API** | `GET /api/v1/events/recommended` — 按用户 tags 匹配活动，权重排序 |
| **算法** | 标签交集计数 + 时间衰减（近期活动加权）+ 地理位置距离（可选） |
| **前端** | Home 页新增"为你推荐"板块，置顶显示 |
| **工作量** | 2 人天 |

#### 1.3 活动搜索增强
| 项 | 说明 |
|---|---|
| **后端** | 搜索支持标题+描述+标签+地点多字段；增加分类筛选、时间范围筛选、价格范围筛选 |
| **API** | `GET /api/v1/events/search?q=&category=&start_after=&start_before=&max_price=` |
| **前端** | Home 页搜索栏增加筛选下拉和标签选择 |
| **工作量** | 2 人天 |

#### 1.4 文件上传基础
| 项 | 说明 |
|---|---|
| **存储** | MVP 阶段本地存储（`uploads/` 目录），后续迁移 OSS |
| **API** | `POST /api/v1/upload` — 返回文件 URL；支持图片压缩 |
| **前端** | 活动创建页支持封面图上传；Profile 页支持头像上传 |
| **依赖** | python-multipart、Pillow（图片压缩） |
| **工作量** | 2 人天 |

#### 1.5 财务管理补全
| 项 | 说明 |
|---|---|
| **后端** | 活动维度财务汇总 API；预算 vs 实际对比 |
| **前端** | Dashboard 增加财务图表（收入/支出饼图、趋势折线图） |
| **工作量** | 2 人天 |

**Phase 1 合计：~10 人天**

---

### Phase 2：差异化功能（2-4 周）

> 目标：建立竞品没有的核心差异化能力

#### 2.1 AI 文案生成
| 项 | 说明 |
|---|---|
| **功能** | 活动前：根据活动信息生成推广文案（适配微信/小红书/微博格式）；活动后：生成参与者分享文案 |
| **API** | `POST /api/v1/ai/copywriting` — 输入活动 ID + 目标平台 → 输出文案 |
| **数据模型** | 新增 `Copywriting` 表（id, event_id, user_id, platform, content, created_at） |
| **前端** | 活动详情页新增"AI 生成文案"按钮；文案结果页支持编辑/复制/下载 |
| **工作量** | 3 人天 |

#### 2.2 SOP 模板库
| 项 | 说明 |
|---|---|
| **数据模型** | 新增 `SOPTemplate` 表（id, title, category, content_json, tags, usage_count, is_public, created_by） |
| **API** | CRUD 接口 + `POST /api/v1/ai/generate-from-template` — 基于模板+用户想法生成定制方案 |
| **前端** | 新增"模板中心"页面；创建活动时可从模板导入 |
| **种子数据** | 预设 5-8 个常见活动类型模板（户外、读书会、音乐节等） |
| **工作量** | 4 人天 |

#### 2.3 活动复盘报告
| 项 | 说明 |
|---|---|
| **后端** | 活动结束后自动汇总：参与率、财务盈亏、用户反馈、AI 改进建议 |
| **API** | `POST /api/v1/events/{id}/report` — 生成复盘报告 |
| **数据模型** | 新增 `EventReport` 表（id, event_id, summary, metrics_json, suggestions, generated_at） |
| **前端** | 活动管理页新增"生成复盘报告"按钮；报告详情页 |
| **工作量** | 3 人天 |

#### 2.4 AI 方案生成增强
| 项 | 说明 |
|---|---|
| **多轮对话** | 支持追问修改（"预算太高了"、"加一个互动环节"） |
| **方案导出** | 支持导出为 Markdown / PDF / Word |
| **方案版本** | 支持同一活动的多个方案版本对比 |
| **工作量** | 3 人天 |

**Phase 2 合计：~13 人天**

### Phase 3：增值体验（1-2 月）

> 目标：提升用户粘性和传播力

#### 3.1 游戏化模块
| 项 | 说明 |
|---|---|
| **数据模型** | `Achievement`（成就定义）、`UserAchievement`（用户成就）、`PointTransaction`（积分流水） |
| **功能** | 签到打卡（每日+积分）、完成任务（首次办活动、参加5场活动等）、排行榜（月度/总榜）、积分兑换（优先报名、专属徽章） |
| **前端** | 新增"成就中心"页面；Profile 页显示积分和徽章 |
| **工作量** | 5 人天 |

#### 3.2 回忆相册
| 项 | 说明 |
|---|---|
| **功能** | 活动结束后上传照片，AI 自动配文；个人时间轴浏览 |
| **数据模型** | `Album`（相册）、`AlbumPhoto`（照片+描述+位置） |
| **前端** | 新增"我的相册"页面；活动详情页可上传/浏览照片 |
| **工作量** | 4 人天 |

#### 3.3 沟通协作（轻量版）
| 项 | 说明 |
|---|---|
| **功能** | 活动内讨论区（报名者可留言）；组织者公告功能 |
| **数据模型** | `Discussion`（id, event_id, user_id, content, parent_id, created_at） |
| **前端** | 活动详情页新增讨论区 tab |
| **工作量** | 3 人天 |

**Phase 3 合计：~12 人天**

### Phase 4：工程质量（持续）

#### 4.1 测试覆盖
| 优先级 | 内容 |
|---|---|
| P0 | 后端核心流程集成测试（注册→登录→创建活动→报名→签到→财务） |
| P1 | API 边界测试（权限、参数校验、并发） |
| P2 | 前端关键路径 E2E 测试（Playwright） |
| **工作量** | 5 人天 |

#### 4.2 数据库迁移
| 项 | 说明 |
|---|---|
| **方案** | SQLite → PostgreSQL（使用 Alembic 管理迁移） |
| **步骤** | 1. 安装 psycopg2 + alembic  2. 初始化 alembic  3. 编写迁移脚本  4. 测试数据迁移 |
| **工作量** | 2 人天 |

#### 4.3 CI/CD
| 项 | 说明 |
|---|---|
| **GitHub Actions** | PR 自动跑 lint + test；main 分支自动构建 Docker 镜像 |
| **部署** | Docker Compose 一键部署到云服务器 |
| **工作量** | 2 人天 |

#### 4.4 性能优化
| 项 | 说明 |
|---|---|
| 后端 | 分页查询（活动列表、报名列表）；Redis 缓存热门活动 |
| 前端 | 虚拟列表（大量活动时）；图片 CDN + WebP 格式 |
| **工作量** | 3 人天 |

## 六、风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| AI API 成本超预期 | Phase 2/3 功能成本失控 | 设置每日调用限制；文案生成缓存相似请求 |
| 数据库迁移丢数据 | 生产环境数据丢失 | 迁移前完整备份；forward + rollback 脚本 |
| 前端重构范围蔓延 | 交付延期 | 严格 MVP 原则，不做"顺便优化" |
| 单人开发瓶颈 | 进度不可控 | 优先高价值功能，低价值推迟或砍掉 |
