## 2. 技术选型

### 2.1 前端

| 模块 | 技术 | 选型理由 |
|------|------|---------|
| 框架 | React 18 + TypeScript | 生态成熟，类型安全 |
| 状态管理 | Zustand | 轻量，适合中型项目 |
| UI组件 | Ant Design 5.x | B端友好，组件丰富 |
| 样式 | TailwindCSS | 原子化CSS，开发效率高 |
| 地图 | 高德地图 JS SDK | 国内体验好，API完善 |
| 图表 | ECharts | 功能强大，文档友好 |
| 构建 | Vite | 快速，配置简单 |

### 2.2 后端

| 模块 | 技术 | 选型理由 |
|------|------|---------|
| 框架 | FastAPI | 异步高性能，自动文档 |
| ORM | SQLAlchemy 2.0 | 成熟稳定，支持异步 |
| 数据库 | PostgreSQL 15 | 关系型，支持JSON |
| 缓存 | Redis 7 | 高性能，支持会话/队列 |
| 对象存储 | MinIO / 阿里云OSS | 图片/文件存储 |
| 搜索 | Elasticsearch (可选) | 全文搜索，后期扩展 |
| 消息队列 | Redis Stream / RabbitMQ | 异步任务处理 |

### 2.3 AI服务

| 功能 | 技术 | 说明 |
|------|------|------|
| 方案生成 | DeepSeek API (v4-flash) | 快速响应，成本低 |
| 方案精修 | DeepSeek API (max模式) | 复杂场景，高质量 |
| 文案生成 | DeepSeek API | 多轮对话，上下文理解 |

### 2.4 部署

| 环境 | 方案 | 说明 |
|------|------|------|
| 开发环境 | Docker Compose | 本地一键启动 |
| 测试环境 | 云服务器 (2C4G) | 验证集成 |
| 生产环境 | 阿里云ECS + RDS | 高可用，易扩展 |

## 3. 核心模块设计

### 3.1 API层设计

#### 接口规范
- RESTful 风格
- 统一响应格式：`{code, message, data}`
- JWT Token 认证
- 请求频率限制

#### 核心API分组
```
/api/v1/
├── auth/          # 认证相关
├── users/         # 用户管理
├── events/        # 活动管理
├── registrations/ # 报名管理
├── finance/       # 财务管理
├── ai/            # AI服务
│   ├── plan/      # 方案生成
│   └── content/   # 文案生成
├── recommend/     # 推荐系统
├── messages/      # 消息系统
└── admin/         # 管理后台
```

### 3.2 AI服务设计

```
┌─────────────────────────────────────────┐
│            AI Service                    │
├──────────┬──────────┬───────────────────┤
│ 方案生成器 │ 文案生成器 │   推荐引擎        │
│          │          │                   │
│ - 多轮对话 │ - 多平台适配│ - 协同过滤        │
│ - 结构化输出│ - 风格控制  │ - 内容标签匹配     │
│ - 上下文记忆│ - 图片配文  │ - 地理位置加权     │
└──────────┴──────────┴───────────────────┘
         │
    ┌────┴────┐
    │DeepSeek │
    │  API    │
    └─────────┘
```

#### 方案生成流程
1. 用户输入想法（文本）
2. 判断模式：直接生成 or 引导式
3. 调用 DeepSeek API，携带系统提示词
4. 解析返回内容，结构化存储
5. 用户确认/修改后，转化为活动草稿

### 3.3 推荐系统设计

```
用户画像 + 活动标签 + 地理信息
        ↓
   多维评分模型
        ↓
   Top-N 推荐列表
```

#### 推荐维度
- 兴趣匹配度（标签重合）
- 地理距离（距离衰减）
- 社交关系（好友参与）
- 时间匹配（历史活跃时段）
- 热度权重（报名人数）

### 3.4 数据流设计

#### 活动发布流程
```
用户创建 → 草稿存储 → 提交审核 → 管理员审批 → 发布上线
   ↓                                    ↓
AI方案转化                          触发推荐更新
   ↓                                    ↓
用户画像匹配                       推送到目标用户
```

#### AI方案生成流程
```
用户输入想法
    ↓
意图识别 (直接生成/引导询问)
    ↓
DeepSeek API 调用
    ↓
结构化解析 → 方案预览 → 用户确认
    ↓
存储到 AI_Plan 表 → 可选转化为 Event
```

## 4. 安全设计

### 4.1 认证与授权
- JWT Token (Access Token + Refresh Token)
- RBAC 角色权限模型
- API 请求签名验证

### 4.2 数据安全
- 敏感数据加密存储 (bcrypt)
- HTTPS 全站强制
- SQL注入防护 (ORM参数化)
- XSS防护 (输入过滤+输出编码)

### 4.3 审计日志
- 关键操作记录（创建/删除/修改）
- 登录日志（IP、设备、时间）
- 异常行为告警

## 5. 扩展性设计

### 5.1 水平扩展
- 无状态API服务，支持多实例
- Redis 集中管理会话
- 数据库读写分离

### 5.2 功能扩展
- 插件化架构，支持自定义模块
- Webhook 支持第三方集成
- 开放API供外部调用

## 6. 部署架构

### 6.1 开发环境
```yaml
# docker-compose.yml
services:
  frontend:
    build: ./frontend
    ports: ["3000:3000"]
  backend:
    build: ./backend
    ports: ["8000:8000"]
    depends_on: [postgres, redis]
  postgres:
    image: postgres:15
    volumes: ["pgdata:/var/lib/postgresql/data"]
  redis:
    image: redis:7
  minio:
    image: minio/minio
```

## 7. 监控与运维

### 7.1 监控指标
- 系统：CPU、内存、磁盘、网络
- 应用：QPS、响应时间、错误率
- 业务：DAU、活动数、转化率

### 7.2 日志系统
- ELK Stack (Elasticsearch + Logstash + Kibana)
- 结构化日志，统一格式
- 链路追踪（可选 Jaeger）

### 7.3 告警策略
- 服务异常即时告警
- 性能指标阈值告警
- 业务指标异常告警
