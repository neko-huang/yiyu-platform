## Windows Batch 脚本闪退问题排查经验

### 现象
双击 .bat 文件后窗口瞬间关闭，完全看不到任何执行输出，无法定位错误位置。

### 根因优先级排序
1. **最高概率：换行符不兼容**
   - 脚本使用Unix LF单行换行符（仅 0x0a）
   - Windows CMD 严格要求 CRLF 双字节行尾（0x0d 0x0a）
   - LF-only 脚本会导致 CMD 在解析 () 代码块、set /p 变量、for 循环等语法时直接崩溃退出，无任何报错输出
2. **次高概率：goto 语法错误**
   - goto 语句写在嵌套的 () 代码块内部
   - Windows CMD 不支持在括号块中执行 goto，会直接终止整个脚本
3. **常见问题：嵌套引号冲突**
   - start 命令的参数中存在嵌套双引号，导致 CMD 解析路径和命令时完全错乱

### 完整修复方案
1. 转换换行符：
   ```bash
   sed -i 's/$/\r/' run.bat
   ```
   转换完成后用 xxd run.bat 验证行尾是否存在 0x0d 0x0a 组合
2. 重构脚本结构：
   - 将所有 goto 从括号块内移出，改用 exit /b 返回逻辑
   - 使用 `start /d "工作目录路径" cmd /k "要执行的命令"` 语法，避免嵌套双引号
3. 兜底防护：脚本所有执行路径的最后都加上 pause 指令，确保无论成功/失败，窗口都会停住等待用户按键，永远不会静默闪退
